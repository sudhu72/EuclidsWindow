KV-cache, GQA, and Multi-Head Latent Attention

Why caching turns cubic into quadratic, how GQA and MLA shrink the memory formula, and the RoPE wrinkle that keeps it honest.

1. Caching stops you re-doing work you already did, so it turns a cubic total generation cost into a quadratic one — the same "don't recompute what you already know" instinct as backpropagation's efficiency trick.

2. GQA shrinks the cache by sharing Keys and Values across several query heads instead of giving every head its own private copy.

3. MLA goes further by squeezing Keys and Values through a small shared bottleneck in the first place — so cheaply that the surrounding weight matrices can be algebraically merged, and the full-size Key and Value never need to be reconstructed at all, at the cost of a small patch to keep positional rotation (RoPE) working.
