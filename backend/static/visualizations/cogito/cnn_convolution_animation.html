Part 3's recipe, worked out: multiply each pair, then sum every product

The edge filter (-1, 0, 1 per row) only ever compares a window's right column to its left column. Inside a flat region, both columns match, so the difference — and the output — is exactly 0. Only when the window straddles the true boundary does the left column see the dim side and the right column see the bright side at once, producing a large spike. Move one more step past the boundary, and both columns are back on the bright side — the difference collapses to 0 again.

The blur filter (every weight 1/9) computes a plain average of the 9 pixels underneath it — no comparison at all. As the window slides from the dim region toward the bright region, the average rises smoothly, one small step at a time, because a growing fraction of the window is covered by bright pixels at each position. Same image, same sliding mechanism — the filter's own weights are the only thing that decided "highlight the boundary" versus "smooth everything into a gradient."
