Does This Agent Actually Work?

An eval engine is the automated system that keeps asking that question at scale. Three pieces of it, made interactive: the pipeline architecture, the two-axis grading that catches "right answer, bad process," and how a Skill's own trigger description gets tested like a classifier.

Each panel below reads top to bottom: what's happening, a try this, and why it matters.

Five Stages, One Task Run at a Time

What's happening: click any stage to see its job, its driving-test-system twin, and which Part of the tutorial builds it. Click "Run one task" to animate a token through the whole pipeline.

Try this: click each stage first, then run a task and watch it visit every one in order — notice the Sandbox Provisioner always runs *before* the Agent Under Test, never after.

Click a stage above, or run a task.
Why it matters: skip any one of these five and the whole system stops being trustworthy — no isolation means one run contaminates the next; no aggregator means every result stays a disconnected anecdote.

Same Four Policies, Two Scores Each

What's happening: run the tutorial's exact toy simulation live — 4 agent policies, 3 tasks each, graded on both outcome accuracy and trajectory score.

Try this: run it once at the default luck rate (0.70) and confirm LuckyPolicy's outcome accuracy vs. its trajectory score; then drag the luck rate down to 0.30 and re-run — outcome accuracy drops with it, but trajectory score stays pinned at exactly 0%, because luck rate never touches *how* it reasons, only how often the guess happens to land.

Score Your Own Trigger Description

What's happening: pick (or edit) a trigger description's topic tags and see it scored against the tutorial's exact 10 held-out prompts — 4 genuinely in-scope, 6 genuinely out-of-scope.

Try this: load Description A, B, and C in turn and watch the score and the specific wrong prompts change — then check the two checkboxes on and off to build your own description and see if you can beat 10/10.

Why it matters: a description "fires" only when every tag it names is present in the request — adding a tag makes it more specific (fewer false positives, more false negatives); removing one makes it broader (the opposite trade). There's no free lunch, only the right-sized description for the job.
