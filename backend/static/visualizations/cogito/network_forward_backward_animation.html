Where's the x in step 7 (blame at the output)? It hasn't arrived yet. ∂loss/∂output = -2×(y-output) only asks "how does the loss react to the output value" — answerable using just y and output. The loss formula, loss = (y-output)², doesn't contain w or x anywhere. Proof: -1.848 above was computed using only 1.0 and 0.076 — x was never consulted and couldn't have changed the answer.

So where does x come from? A completely separate formula: output = w·x + b, differentiated with respect to w. That's the only formula that mentions x at all, and it only gets used one step later — that's why 0.18 and 0.13 (B1 and B2's outputs, playing the same role x played) only show up in step 7's log entry, not step 6's.

Then where does the negative sign in -2 come from, if not from w·x+b? From the loss formula's own definition, not from the output formula. Let e = y - output, so loss = e². Then ∂loss/∂output = 2e × ∂e/∂output = 2e × (-1). That -1 is ∂(y-output)/∂output — it's -1 purely because output is subtracted inside y-output. Meanwhile ∂output/∂w = x on its own, with no minus sign anywhere — addition and multiplication don't manufacture negative signs. A specific weight (like w_C2 = -0.4) can happen to have a negative value, but that's a fact about that number, not something the derivative rule inserted.

Two separate formulas, two separate questions, each answered using only the symbols that formula actually contains. The chain rule just multiplies the two finished answers together at the end — it never blends their internals.

Look at how any neuron's raw value is computed: C1_raw = w_C1 × B1_output + w_C2 × B2_output + b_C. That's just two multiplications added together. For a simple product w × x, calculus gives two symmetric facts for free: ∂(w×x)/∂w = x and ∂(w×x)/∂x = w — in a product, each variable's sensitivity is always the other variable.

Asking "how does C1 react to w_C1?" gives back B1_output = 0.18 — used for ∂loss/∂w_C1, which updates the weight and never travels anywhere else.

Asking "how does C1 react to B1_output?" gives back w_C1 = 0.6 — used as the blame handed to B1, which continues the backward pass and has nothing to do with updating anything at this layer.

Same formula, same multiplication, two different questions about its two different factors — and because it's a product, each answer is simply whatever the other factor happens to be. That's the entire reason gradients use the input and blame uses the weight: they're reading the two halves of the same product rule.

A real-world version you already know by instinct: running a lemonade stand. revenue = price × cups sold. Charge $2 a cup, sell 50 cups, revenue is $100. Raise the price by $1, keeping sales at 50: revenue goes up by 50 × $1 = $50 — sensitivity to price is exactly the number of cups sold, the other factor. Sell one more cup instead, keeping the price at $2: revenue goes up by exactly $2 — sensitivity to cups sold is exactly the price, the other factor again. output = w × x has the same shape: w is the price, x is the units sold. Nudging the weight is like raising the price — the payoff scales with however much is flowing through (x). Nudging the input is like selling more units — the payoff scales with whatever the "price" (w) currently is.

Is blame also a derivative — with respect to x? Yes: blame = ∂loss/∂x, exactly parallel to a weight's gradient being ∂loss/∂w. B1's blame (-1.109) is ∂loss/∂(B1_output), since B1_output is playing the role of x in C1's formula. This is exactly why blame keeps flowing backward: B1_output is itself the output of an earlier calculation, so ∂loss/∂(B1_output) becomes B1's own blame — used both to compute ∂loss/∂w_B1 and to produce a fresh ∂loss/∂x (this time with respect to A1's output) to hand one layer further back. Every "blame" number in the network is the same quantity, ∂loss/∂x, recomputed at each layer.
