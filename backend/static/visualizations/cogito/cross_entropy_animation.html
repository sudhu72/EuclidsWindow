Why -log(p) and not some other harsh-punishing curve? Play Twenty Questions: narrowing down a hidden object with yes/no questions, always splitting what's left roughly in half. Finding 1 of 8 equally likely objects takes log₂(8) = 3 questions; 1 of 1000 takes about log₂(1000) ≈ 10. The number of yes/no questions needed to pin something down is exactly -log₂(its probability) — rare things take more questions, common things take fewer.

Cross-entropy is scoring exactly that: if the model gave the true outcome probability p, then -log(p) is "how many questions it would have taken to arrive at that outcome, given how the model was betting." Confidently right needs almost no questions — tiny penalty. Confidently wrong means the truth was buried among many unlikely alternatives — a huge number of questions, a huge penalty.

This already existed in the real world, in Morse code. Samuel Morse gave the shortest code — one dot — to "E," the most common letter, and long codes to rare letters like "Q." Cheap codes for likely things, expensive codes for unlikely things, to keep the average message short. Claude Shannon formalized this in 1948, proving -log(p) is the mathematically optimal code length for something with probability p — cross-entropy loss borrows that exact insight to score a model's predictions.

Note on units: the curve above uses natural log (matching the loss formula machine learning frameworks actually compute), while the box-counting uses log base 2 (matching "number of yes/no questions," a whole number of bits). Same story, different-sized rulers — like measuring one distance in miles versus kilometers.
