Attention's matrix math

The general kernel-then-normalize-then-blend recipe, why softmax is one choice among many, the √d scaling derivation, and multi-head bookkeeping.

1. Kernel κ
A[i,j] = κ(Q[i],K[j])
→
2. Normalize
Z⁻¹A (rows sum to 1)
→
3. Blend
Y = Z⁻¹AV

The two-step recipe underneath attention: (1) score every query against every key with some similarity function κ — a "kernel" — and (2) turn each query's row of scores into a valid probability distribution so a weighted blend of Values makes sense as an average. Y = Z⁻¹AV, where Z is a diagonal matrix holding each row's total score.

Softmax attention is the special case where κ(v,w) = exp(⟨v,w⟩/√d). Plug that specific kernel into the two-step recipe, and "divide each exponentiated score by its row's total" — Z⁻¹A — is exactly the softmax function. Nothing about the recipe *requires* this particular kernel; it's simply the best-understood, most common choice.

Why √d specifically? If a query and key vector's entries are roughly random with mean 0 and variance 1, their dot product sums d independent terms, each with variance 1 — so the dot product's own variance is d. Dividing by √d brings that back down to 1, regardless of how large the embedding dimension gets. Without this, wider models would have systematically larger, less comparable raw scores purely from having more dimensions to add up — nothing to do with tokens actually being more related.
